# Execution and complete-stream history checks

Native Pilot A now records every selected-action execution result, including
refusals and exceptions, with private before/after full registered-seat zone,
life/counter/commander snapshots and the actor's mana pool. Actor policy-memory
sets are captured at execution and automatic mana-planning boundaries. This
supports reduction of future payment failures; it does not reconstruct missing
historical memory or approve whole-cost rollback automatically. Omniscient
records stay private and are never pilot observations or trusted training data.

A minimal null-action call reproduced a controller NullPointerException on the
prior executable. The controller now refuses null before dereferencing it.
Wrong-priority and consumed-selection refusals remain intact. Two fresh native
four-controller fixtures yield identical409-row/204-call tapes,2 successful
executions with actual mana payment,3 refusals with unchanged recorded state and
pool,0 unencoded values and0 independent mana transition gaps. This is an API
boundary repair, not a newly discovered Magic rules defect. The house-profile
regression passes on the combined executable. All316 root Python tests pass.

The new independent history reader checks the whole stream's announcement and
removal identities, LIFO resolution order, life-event continuity and consistency
of recorded terminal seats/life/winner. It also checks unchanged refused-action
transitions where snapshots exist, and retains changed/missing ones for review.
Life-zero consistency does not prove that loss-prevention effects or SBAs were
derived correctly. Countered/removed spells need causal effect review. It never
grants rules approval or learning admission.

This is a notification/evidence discrepancy requiring review, not proof of an
illegal game action. No card-name exception or inferred missing event is used
